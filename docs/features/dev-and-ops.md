# Dev process & CI

Detailed per-feature notes moved out of `CLAUDE.md` (text unchanged, original order). `CLAUDE.md` keeps only the standing rules; add a new note for a change **here**, in the file for its area.

## Contents

---

**CI runs the type check and the unit tests on every push and pull request (v2.17.11)** — `.github/workflows/ci.yml` (Node 22, pnpm from the `packageManager` field, `pnpm install --frozen-lockfile`, `pnpm check`, `pnpm test`; on pushes to `main`, `runlogtest` and `develop`, on every pull request, and by hand; a newer run on the same branch cancels the older one; 20-minute limit). The tests are offline (no database, network or AI), so the job needs no services. It sits alongside `no-runtime-ai.yml`, which is unchanged. **The six long-standing failures in `server/running_sheet.test.ts` were stale tests, not bugs, and are fixed** (so the suite is green and a red run means something): sheet creation by an Observer is refused (Observers have view and export access only), a Member creates a sheet on an active operation; `sheet.delete` needed `softDeleteSheet` in the `./db` mock; `row.update` needs an active sheet and operation; and a Member may only certify / unlock rows that carry their own CIN, so those tests now sign in as a member with a CIN and a row that has it. **If CI goes red, fix the test or the code — do not leave a known failure in the suite.** Not done: a branch-protection rule requiring the check before merge (a GitHub setting), browser smoke tests, and splitting `db.ts` / `routers.ts`.

**Browser smoke tests (v2.17.13)** — `e2e/` (Playwright, `pnpm test:e2e`, `e2e/README.md` has the setup) now drives the real app in Chromium: `auth.setup.ts` signs in once per run and saves the session (`e2e/.auth/user.json`, git-ignored — the login endpoint is limited to 20 attempts per 15 minutes per IP, so one sign-in per run, not per test); `smoke.spec.ts` (1) creates an operation and a running sheet, adds a row with an observation and the officer's own CIN, reloads to prove it was saved, clicks the CIN to certify and checks the row shows **Locked** and no longer opens an editor, and (2) opens every main page that doesn't need Google Maps and fails on the error screen ("An unexpected error occurred.") or any uncaught script error; `voice-offline.spec.ts` (the older Golden Rule check) was repaired — it had been failing since RS Quick Entry started requiring a selected running sheet and voice input was switched off (`VOICE_INPUT_DISABLED`), so it now makes a sheet, selects it in `runlog_map_settings` and asserts no request leaves the app's own origin while Quick Entry is open offline (it still exercises the Voice button if the feature is turned back on). **CI** — `.github/workflows/e2e.yml` (own workflow, so `ci.yml` stays fast and offline): MySQL 8 service, `drizzle-kit migrate`, `scripts/dev/create-admin-user.ts`, the app started with `NODE_ENV=development`, `playwright install --with-deps chromium`, then `pnpm test:e2e`; failure screenshots, traces and the app log are kept as an artifact for 7 days. **Things that cost time to find, so they are written down:** the server needs both `VITE_APP_ID` and `JWT_SECRET` or the session cookie is rejected ("Session payload missing required fields") and sign-in looks like it does nothing; a CIN added to a row is checked against registered users (green tick) and committed with the round **+** button — Enter alone doesn't add it; after adding, a CIN shows red until its owner clicks it, and a row locks (shows **Locked**) only when every CIN on it has certified; the CIN pill is an `<input>` while editing, so its text isn't in `innerText`. **Not covered yet:** Mapping / RS Mapping (Google Maps isn't reachable from CI), the Target Logger and Target Registry flows, Import Target, exports, and phone-width layouts. Checked against a local MariaDB 10.11 (all 132 migrations apply) with the full suite run repeatedly; the first run on GitHub (MySQL 8) is the check that matters for the workflow itself. Sheet-row tests add one operation and sheet per run (`Smoke <timestamp>`) and delete nothing, so only point them at a throwaway database.

**`routers.ts` split into one file per area (v2.17.14)** — `server/routers.ts` was 10,266 lines; it is now 93 lines that only put the areas together, and each of the 40 API areas is its own file in `server/routers/` (`profile`, `auth`, `passkey`, `operation`, `sheet`, `row`, `attachment`, `target`, `intelligence`, `ctoRoster`, `admin`, … — the same names and order as before, so every client call such as `trpc.sheet.create` is unchanged). The guards, shared input schemas and small shared helpers that used to sit at the top of the file are in `server/routers/_helpers.ts` (each now `export`ed; a router file imports only the ones it uses). **Pure move: no code inside any procedure changed** — only the file it lives in, its indentation, its import paths (`./x` → `../x`, including the dynamic `import()`s) and its imports (each file keeps only what it uses). Checked three ways: `pnpm check`; all 1,587 unit tests (the tests that mock `./db` still work because the new files import the same module); and a comparison of the old and new `appRouter` — 381 procedures each, no missing or extra, every one with the same type (query/mutation), input count and middleware count. **How the split was done, in case `db.ts` or another big file is next:** a throwaway script cut the file by its top-level `name: router({ … }),` entries and wrote one file each; TypeScript's own organise-imports removed the unused imports; Prettier formatted the result; the old and new routers were then compared. **Next:** `db.ts` (19,199 lines, 353 exported functions in 63 `// ─── Section ───` blocks) — to be split the same way into `server/db/<area>.ts` with `db.ts` kept as a file that re-exports everything, so no other file's `import … from "./db"` changes.
