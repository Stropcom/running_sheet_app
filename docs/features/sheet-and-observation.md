**Shortcut chip order (v1.192.0)** — the quick-insert chips on the main running sheet (Target / Shortcuts panel) and in the RS Quick Entry pop-up are no longer draggable and have no per-sheet order in `localStorage` any more. The order is the **Shortcuts page** list, saved on the server (`shortcuts.sortOrder`, migration 0123; `shortcuts.list` returns it sorted; `shortcuts.reorder` is admin-only like add/edit and must be sent every id; new shortcuts go to the end; `ensureShortcutOrder` numbers any unplaced shortcut at startup — the old chip order first, then A–Z). The pure rule is `orderRsChips` in `shared/rsChips.ts` (tested in `server/rsChips.test.ts`), used by both screens: shortcut chips in list order, and the target's own chips fixed: a block (HBF, V1F/V1…Vn, TGT) straight after SC, and **HB straight after AR** (v1.193.1 — between AR and CP in the default order; it follows AR if AR is dragged elsewhere). **Vehicle colour (v1.193.1)** is always lower case — `shared/vehicleColour.ts` (`lowerVehicleColour` for the Colour field, `lowercaseLeadingColour` for display text): the Colour input lower-cases as you type, `composeVehicle`/`composeVehicleTargetName` write it lower case, the document-import vehicle parser returns it lower case, `vehColour` is lower-cased on the server in the shared structured-target schema, and `formatIntelVehicle` (every Intelligence folder / profile vehicle label) lower-cases the colour at the start of the description. Vehicles already saved keep their old V1F text until the target is edited and saved again (the Intelligence folder shows them lower case regardless). The DEP, ARR and #1–#10 wild-field chips were removed from both screens (the data columns stay). Changing the order of the chips = drag on the Shortcuts page, nowhere else. **v1.192.1:** Shortcuts is no longer a top-level sidebar folder — it is a sub-folder of **Administration** (list view and the tile-view menu), which now has its own colour (emerald; sub-folders: Archive teal, Audit Log fuchsia, Draft Mode orange, Intel Export violet, Recycle Bin red, Shortcuts yellow, Help sky). Administration's sub-folders are alphabetical with **Help always last** (`isAdministrationPath` in `DashboardLayout.tsx` is the one list of pages that highlight the folder). The old "hover Shortcuts to open the Shortcuts Reference panel while typing an observation" still works from the Shortcuts sub-folder, but only while Administration is expanded.

**Vehicle lists (v1.193.0)** — vehicles written one after another in an observation are punctuated as a list: two get "and" (`A and B`), three or more get commas with "and" before the last and no comma before it (`A, B and C`). The pure rule is `shared/vehicleList.ts` (tested in `server/vehicleList.test.ts`): a vehicle ends at its `(Vehicle REGO)` bracket and what sits between two brackets must look like the next vehicle's description (a bare rego, "…, bearing WA registration …", or empty — narrative, a new line or sentence punctuation between them leaves it alone, and a gap that opens with a body-type word like "station sedan" is the previous vehicle's own description). A list with any unpunctuated link is rewritten in full, so one that grew a vehicle at a time becomes `A, B and C`. **Articles (v1.194.0):** every *described* vehicle in a list also gets `a` / `an` in front (a capital `A` / `An` when it opens a sentence or the observation; a vehicle that is just a rego gets none; an existing article is kept; the colour is lower-cased) — `A white Lexus …, a white Toyota … and a silver Ford …`. The first vehicle's description start is found by looking back in its sentence for a colour-led run of plain words up to `, bearing …`, so narrative before it is left alone. A list that is already fully right is never touched. Applied live on Space right after a vehicle bracket and when the field loses focus — in `ObservationCell` (`SheetDetail.tsx`) and the RS Quick Entry textarea (`IntelligenceMapping.tsx`, also at submit) — and again at save time in `normalizeObservationPunctuation` (`server/db.ts`), whose Rule 1 (comma after every `(Vehicle …)` bracket) skips the bracket in front of a list's final "and". Check Sheet flags older rows (`vehicle-list-unpunctuated`, one finding per list, one-tap fix) via `checkVehicleLists` in `server/sheetCheck.ts`. Locked rows are never changed.

**Observation tidy-up (v1.195.0)** — one pass over text an officer *typed*, doing what they'd otherwise fix by hand: a capital at the start, after each full stop and at the start of each line; one space between words; a space after a comma that has none (`1,000` untouched); and a full stop at the end (only on click-out, and only for 2+ words). The pure rule is `shared/observationTidy.ts` (`tidyObservation`, `tidyObservationAtCaret`, `justTypedSpaceAfterBracket`; tested in `server/observationTidy.test.ts`); it runs `joinVehicleLists` first so vehicle lists and tidy-up agree. It never lower-cases or rewrites wording and leaves alone: a bare "tv", a sentence opening with a colour phrase, a rego/number or inner-capital token (iPhone), text after abbreviations (etc, cnr, st…) or a single-capital initial, and anything inside brackets. **Chips, shortcuts, pre-typed sentences and Target Logger text are never changed**: it runs only on typing — `ObservationCell` (`SheetDetail.tsx`) tidies on blur only if the draft differs from the saved value, and the RS Quick Entry textarea only if `rsInlineTypedRef` (set in the textarea `onChange`, reset on close) is true, otherwise just `joinVehicleLists` as before. Triggers: Space after a `)` and click-out. Deliberately **not** added to the server's `normalizeObservationPunctuation`. Considered and not built: tagging each chip with a phrase kind (sentence / noun phrase / name) so back-to-back chips could be joined — it would alter chip output.

**Typing slips are repaired (v1.206.7)** — part of the observation tidy-up (`repairEdits` / `repairObservation` / `repairObservationAtCaret` in `shared/observationTidy.ts`, run first by `tidyObservation` and `tidyObservationAtCaret`, so same triggers and same "only text that was typed" guard; tests in `server/observationTidy.test.ts`). It fixes what a Quick Entry sentence edited by hand looked like — "CORNELL exited the vehicle, entered. 64 Sewell Streetand and continued out of sight." → "… entered 64 Sewell Street and continued out of sight.": (1) a **doubled function word** (`and|the|a|an|of|to|at|with|for|from|or|but`, case-insensitive, any run of repeats) keeps the first and drops the rest — words that can legitimately repeat ("that that", "had had") are not on the list; (2) a **doubled comma** (`,,` or `, ,`) becomes one; (3) a **full stop in the middle of a sentence** is removed only when it is clearly a slip: straight after a joining word (`and the of to at with for from or but into towards via onto`) when a number or lower-case word follows, and straight after "entered" only when an address follows (number then a capitalised word) — "HOGAN entered. SANTOS walked off." and "entered. 2 males exited." are left alone; (4) a **street type glued to "and"/"then"** ("Streetand") gets its space. Nothing inside a bracket is touched, and no word's spelling or case changes. Not added to the server's `normalizeObservationPunctuation` and Check Sheet does not flag older rows for these yet.

**Joining words between pieces (v1.196.0)** — part of the observation tidy-up, automatic, same triggers (Space after a bracket, click-out) and same "only text that was edited" guard. The pure rule is `shared/sentenceJoin.ts` (`sentenceJoinEdits`, `wholeSentenceChips`; tests in `server/sentenceJoin.test.ts`), run by `tidyObservation` / `tidyObservationAtCaret` after the vehicle lists and before the capitals/spacing rules; `joinObservationPieces` is the joining without the capitals/full-stop fixes, used for Quick Entry text made only from chips. It only ever fills the **gap** between two pieces and never rewrites, removes or re-cases a word: (1) a **full stop** between two whole sentences — a whole-sentence phrase (built-ins: Surveillance commenced / Surveillance ceased / Out of sight / Continued out of sight / PHOTOGRAPH/S TAKEN, plus any shortcut expansion that is plain capitalised words, 2–6 words, not ending on a joining word, no brackets/commas/digits/[blanks]) followed by a capitalised word that isn't a joining word (after "Surveillance commenced/ceased" only if the next word plainly opens a sentence, since a place may follow); (2) **"at"** between "Surveillance commenced/ceased" and a street address (digit-led, full street type); (3) **"and" / commas** between people introduced back to back as `Given SURNAME (SURNAME)` — `A and B`, `A, B and C` — a capitalised sentence opener (Seen, Then, Vehicle…) is never taken for a given name. The comma after a `(Vehicle …)` bracket already happens at save (`normalizeObservationPunctuation`), so it is not repeated here. Target Logger buttons make whole new rows and are never joined; `[route]`-style blanks are never touched. The shortcuts the main sheet and Quick Entry pass in (`sentenceChips`) come from the Shortcuts page. To add a rule, add it to `sentenceJoinEdits` with a test, and keep it to filling a gap. **Fourth rule (v1.200.1):** "continued out of sight" straight after the place someone entered (`enteredPlaceEdits`) — "entered Crooked Spire Coffee & Art House Midland continued out of sight" → "… Midland **and** continued out of sight" (a capitalised "Continued out of sight" gets a full stop instead). It only fires when everything between the last "entered" in the sentence and the phrase is plainly a place (capitalised words, numbers, "&", an optional leading "the" and a bracketed short form) — "entered the car park", "SANTOS continued out of sight" and anything already joined are left alone; the comma in "…the car park, entered" is not touched. **Fifth rule (v1.200.4):** "A" / "An" before a single full vehicle that opens its sentence (`vehicleArticleEdits`) — "white Lexus NX350h station sedan, bearing WA registration 1TDM414 (Vehicle 1TDM414), parked…" → "A white Lexus …". It needs the same shape the list rule looks for (a colour-led description running up to ", bearing … (Vehicle …)") at the very start of the sentence, observation or line; a description with an article already, one with narrative before it ("Seen leaving in white Lexus…", "Observed …") or no colour is left alone, a capitalised colour is lower-cased, and a vehicle that is part of a list is left to the list rule (no double article). Because it lives in `sentenceJoinEdits` it also runs on chip-only Quick Entry text (`joinObservationPieces`), so the V1F chip at the start of a sentence now gets its "A". Check Sheet does not flag older rows for this. **Entity extraction (v1.196.1):** the joining does not change what `extractEntitiesFromText` finds (same people, vehicles and places before and after — tested in `server/sentenceJoin.test.ts`); the only effect was a joining word or comma leaking to the front of a person's `fullDescription` ("and Karim Elias NAJJAR"), which extraction now strips for persons (this also fixed hand-typed lists).

**New Running Sheet team buttons (v1.200.0, migration 0124)** — the "Add team" buttons in the New Running Sheet dialog (`OperationDetail.tsx`) only list teams with `teams.offerOnNewSheet` true (default true; set per team by the **Offer on New Running Sheet** tick in the Team dialog, `admin.createTeam/updateTeam`). The migration switched it off by name for PTT, Capability, Admin/Administration and Investigators/Investigator, so Western's dialog offers TEAM 1 and TEAM 2 only; any other team or Command keeps its buttons until ticked off. The sheet's own roster "Add team" buttons (`SheetDetail.tsx`) are separate and still list every team.

**Address suggestion location bias (v1.200.2)** — Google address/place suggestions in the observation field (`useAddressSuggestions`, `AddressSuggestDropdown.tsx`; running sheet and Quick Entry) lean towards a 50 km circle around where the officer is, restricted to Australia but never limited to the circle. The position is **followed** (one shared `watchPosition` in `lib/devicePosition.ts`, low-accuracy mode, paused while the page is hidden, one watch however many observation cells are mounted), not read once. Only a **good fix** counts (`shared/addressBias.ts`: accuracy ≤ 2 km, `USABLE_FIX_ACCURACY_M`): a laptop's internet-address guess or a VPN/hotspot position reports tens of km and is ignored, and a poor reading never discards the last good one. Order: last good position → Perth CBD (`PERTH_FALLBACK`); `chooseBiasCentre` takes an optional fallback (e.g. an operation's area) that nothing passes yet. Known addresses from Intelligence are still listed first and are not location-based. The Map page's own address search biases to the map centre and is unchanged. Tests: `server/addressBias.test.ts`.

**Check Sheet: a mistyped "Vehicle" is a short spelling finding (v1.200.3)** — a bracket such as `(Vehcle 1TDM414)` used to be mined as a different vehicle from `(Vehicle 1TDM414)`, so Check Sheet raised a long Consistency finding quoting both rows ("…look like the same vehicle written two different ways"). `misspeltVehicleKeyword` / `checkVehicleKeywordInText` (`server/sheetCheck.ts`) now spot a near-miss of the word *Vehicle* (within 2 edits, a swapped pair of letters counts as one) directly in front of a plate-shaped token, in a bracket or in plain text, and report `"Vehcle" — did you mean "Vehicle"?` as a **Spelling** finding with the usual one-tap fix (`vehicle-keyword-misspelt`, short snippet). The matching long Consistency finding is suppressed for that pair. Ordinary words never match: it needs a near-miss of "vehicle" followed by a rego with letters and digits.

**Photos on a running sheet row can be resized (v2.1.0)** — each photo in `ObservationAttachments` (`SheetDetail.tsx`) has a small **corner handle** at the bottom right of the picture (`components/ResizablePhoto.tsx`): **drag** it to make the photo bigger or smaller (the picture keeps its shape; pointer events, so mouse, finger and pen all work), **double-click** it to put the photo back to the normal size (a third of the cell, 90–160 px). The size is **display only and per device**: it is remembered per photo in `localStorage` (`runlog_photo_w_<attachmentId>`, `photoWidthKey`), nothing is written to the sheet or the server, and **the printed export keeps its own fixed size** (`attachmentImagesHtml`, unchanged). The rules are pure in `shared/photoSize.ts` (tested in `server/photoSize.test.ts`): never below 90 px, never wider than the row the photo sits in, never past 900 px, and a junk stored value is ignored (`clampPhotoWidth`, `parseStoredPhotoWidth`). The handle is a button that stops the click, so tapping the photo still opens the full-size view and tapping the handle does not. The delete cross and the CIN / entity pills stay where they were. Checked in a headless browser against the dev database (three photos on one row): drag bigger, reload keeps it, drag to the minimum, double-click resets, photo click opens the lightbox, phone width has no sideways scroll.

**No closing full stop after a word the sentence can't finish on (v2.4.2)** — the click-out full stop of the observation tidy-up (`tidyEdits` with `final`, `shared/observationTidy.ts`) used to go after whatever the last word was, so an observation left as "HOGAN entered" (the officer clicked out before adding the place, or the next chip) became "HOGAN entered." and the rest then arrived as "entered. 64 Sewell Street" — the slip the v1.206.7 repair rule has to undo. It now skips the closing stop when the last word is in `UNFINISHED_ENDINGS` (entered, and, the, a, an, of, to, at, with, for, from, or, but, into, towards, via, onto, then, while, who); "HOGAN exited" and "HOGAN entered Flight Club Fremantle" still get theirs. Words that can legitimately end a sentence ("in", "on", "up", "off") are deliberately not on the list. Only the closing stop changed — the server's `normalizeObservationPunctuation` never added full stops, and the repair rule is as before. Tests: `server/observationTidy.test.ts`.

**A model name is no longer bracketed as a registration (v2.14.3)** — typing a model like **C200**, NX350h, SR5 or RAV4 in a vehicle description ran into the live "looks like a rego" rule (3–8 letters and digits, `detectVehicleMentionTrigger`), so Space after it wrote `(Vehicle C200)` and Intelligence then listed C200 as a second vehicle ("A blue Mercedes Benz C200 (Vehicle C200), sedan, bearing WA registration 1FAB007 (Vehicle 1FAB007)"). `followsVehicleMake` (`shared/vehicleModel.ts`, tested in `server/vehicleModel.test.ts`) now stops the trigger when the word comes straight after a make written in the same description — a make, then at most two plain words (model, trim), no comma, bracket or "registration / rego / plate / WA…" in between ("Mercedes Benz C200", "Toyota Hilux SR5"); a plate introduced by "registration" / "rego", or standing alone, is bracketed as before. No list of models is kept: the make list is `VEHICLE_MAKES_PATTERN`, moved from `server/db.ts` to `shared/vehicleModel.ts` (db.ts re-exports it). Both the running sheet and RS Quick Entry use that one trigger. A plate typed straight after a make with no "registration" word ("Toyota 1ABC234") is now left unbracketed — the officer types the bracket, or the next Space after "registration" does it. **Check Sheet** flags rows already saved this way (`checkModelBrackets`, `model-bracketed-as-rego`, Formatting, one-tap fix removes the stray `(Vehicle C200)`): the bracketed word must be right after a make AND a different `registration … (Vehicle …)` bracket must follow in the same sentence, so a real plate after a make isn't flagged. Tests: `server/vehicleModel.test.ts`.

**Check Sheet flags typing slips and missing joining words (v2.14.0)** — the live tidy-up rules now also run over saved rows, so anything missed at the time is caught: `checkTypingSlips` (`ruleId` `typing-slip`: doubled function word, doubled comma, a stray full stop mid-sentence, a street type glued to "and"/"then" — from `slipEdits` in `shared/observationTidy.ts`, which is `repairEdits` plus the glued street type, positions in the original text) and `checkJoiningWords` (`joining-word-missing`: a full stop between two whole sentences, "at" after "Surveillance commenced/ceased", "and"/commas between people, "and" before "continued out of sight" after an entered place, "A"/"An" before a single vehicle opening a sentence — all of `sentenceJoinEdits`, `shared/sentenceJoin.ts`), both in `server/sheetCheck.ts`. One finding per edit with the usual one-tap fix (`editFindings`: the fix is the edit widened to the neighbouring words, then to a unique stretch of the row). **Only the safe set**: each rule removes an obvious slip or fills a gap; nothing re-cases or rewrites a word. **Not included, deliberately:** the capitals / spacing / closing full stop of `tidyObservation` — they assume the text was typed, and on a saved row a chip or shortcut can't be told from typing. The joining rule uses the built-in whole-sentence phrases only (the Shortcuts page's whole-sentence expansions are not passed in). Locked rows are never changed, as before. Tests: `server/sheetCheckGrammar.test.ts`. The 2,400 synthetic dev rows produce no findings (they are already clean), so the rate on real sheets is not yet known — look at the first real Check Sheet run for false positives.

## The first row of a sheet comes with the opening and the whole team (v2.44.0)

- **What.** The first row of a running sheet is nearly always "Surveillance commenced in the vicinity of [address]" with the whole team on it. So when a row is made on a sheet that **has no rows yet**, it now comes with **"Surveillance commenced in the vicinity of "** already written and **every CIN on the sheet's team roster already on it** (team leader first, then CIN number, then name — the order the sheet shows). Pressing **Add Row** on a new sheet opens that row's cell for typing with the cursor after "of ", ready for the address (the on-screen keyboard is not suppressed, unlike a continuity-card tap). The row's time is set the way it always is (Set time).
- **Only fills in what is missing.** Text an officer or a chip has already written is never replaced: a first row made by Quick Entry or the map's Quick Entry keeps its own text and just gets the team. A sheet with a row already is left alone, so the second row starts empty with nobody on it. Delete every row and the next one is again "the first". A sheet with no team roster gets the opening and no CINs.
- **One rule, one place.** `shared/firstRow.ts` (`rosterCins`, `firstRowFill`, `FIRST_ROW_OBSERVATION`, tested in `server/firstRow.test.ts`) is applied in the server's `row.create` (`server/routers/row.ts`), so Add Row, Quick Entry, the map's Quick Entry and anything else that makes a row get the same. CINs are checked against registered users exactly as `member.add` does (an unregistered name on the roster is skipped), added in roster order, each with its own `member_added` audit entry; the `row_created` audit entry says the row was filled in automatically and with how many CINs. `row.create` now returns `autoFilled`.
- **Offline.** `autoFirstRow: false` is passed by the offline sync and the draft-mode row creator (`offlineSync.ts`, `useOfflineMutations.ts`), which add a queued row's CINs themselves — so nothing is added twice. A row made offline is not pre-filled.
- **Checked:** unit tests for the rule; the server path against a real database (opening + three CINs in order with audit entries; typed text kept; second row blank; opt-out; unregistered CIN skipped); `e2e/screens.spec.ts` ("The first row of a sheet comes with the opening and the whole team on it") and the smoke, sheet and photo tests, which now open the pre-filled first row (`openNewRowCell` in `e2e/helpers.ts`); looked at on laptop and phone widths. **Note for tests:** in the browser test run the page can lose window focus a moment after a cell opens by itself, which saves and closes the cell (its normal save-on-blur); the new test reads the cell in one step for that reason.
